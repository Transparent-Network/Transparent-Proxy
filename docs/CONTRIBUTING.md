# Contributing to Transparent-Proxy

まずはこのプロジェクトに興味を持ってくれてありがとうございます 🙌
Transparent-Proxy は、制限環境での動作検証を目的としたプロキシプロジェクトです。

このドキュメントでは、**バグ報告・機能提案・コード貢献**の方法をまとめています。

---

## 📌 前提

* Git / GitHub の基本操作が分かっていること
* Node.js **18 以上**（推奨）
* JavaScript / TypeScript の基礎知識
* Cloudflare Workers（または同等のエッジ環境）の基本理解があると尚良し

---

## 🐛 バグ報告（Issues）

バグを見つけた場合は **GitHub Issues** から報告してください。

### バグ報告に含めてほしい情報

* 発生している問題の内容
* 再現手順（できるだけ具体的に）
* 期待していた挙動
* 実際の挙動
* 使用環境

  * Node.js バージョン
  * OS
  * Workers / 実行環境
* エラーログ（あれば）

※ スクリーンショットやログの貼り付けは大歓迎です。

---

## ✨ 機能提案（Feature Request）

新機能の提案も歓迎です。

Issue 作成時には以下を意識してください：

* どんな問題を解決したいのか
* どのような使い方を想定しているか
* 既存機能との関係

「こういう用途で使いたい」というレベルのラフな提案でもOKです。

---

## 🔧 開発環境のセットアップ

```bash
# リポジトリをクローン
git clone https://github.com/kotopiro/Transparent-Proxy.git
cd Transparent-Proxy

# 依存関係をインストール
npm install

# 開発用起動（例）
npm run dev
```

※ 実際のスクリプト名は `package.json` を確認してください。

---

## 🌱 ブランチ運用ルール

* `main` : 安定版
* `feature/*` : 新機能追加
* `fix/*` : バグ修正
* `docs/*` : ドキュメント修正

例：

```bash
git checkout -b feature/add-cache-support
```

---

## 🧪 テストについて

* 新機能を追加する場合は、可能な限りテストや検証手順を明記してください
* 既存機能を壊していないかを必ず確認してください

（テスト基盤が未整備な部分もあるため、**手動検証でもOK** です）

---

## 📐 コーディングルール

* 可読性を最優先
* マジックナンバー・ハードコードは避ける
* 意味のある変数名を使う
* 大きな処理にはコメントを付ける

### 推奨

* Prettier / ESLint に準拠
* async / await を使用

---

## 📤 プルリクエスト（PR）の出し方

1. Fork する
2. 新しいブランチを作成
3. 変更をコミット
4. Pull Request を作成

### PR に含めてほしい内容

* 変更内容の概要
* 関連する Issue 番号（あれば）
* 動作確認方法

---

## ⚠️ 注意事項

* 悪用を目的としたコード・説明は拒否されます
* 法律・利用規約を必ず遵守してください

---

## 📜 ライセンス

本プロジェクトはリポジトリ記載のライセンスに従います。
貢献されたコードも同ライセンスのもとで公開されます。

---

## 🙏 最後に

小さな修正、ドキュメント改善、誤字修正だけでも大歓迎です！
気軽に Issue / PR を投げてください。
